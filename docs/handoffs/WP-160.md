## summary

Implements handoff §9.5 as a pure layer-1 package: one call computes the minimum v1
Polymarket, reference, lifecycle and quality features once per event and returns an
immutable, content-addressed `FeatureSnapshot` or a typed refusal. Registry `FEATURES_V1`
(33 versioned definitions — the reviewer's item-for-item map confirms the exact §9.5 list,
nothing dropped, renamed, or extra) is bound to the computation fail-closed: an uncomputed
registered feature or an unregistered computed feature refuses the whole snapshot.
Canonical JSON (sorted keys, safe integers only, no null, `-0`/NaN refused), SHA-256
content address under a versioned domain prefix, byte identity across construction orders
and clock movement. Division policy: 34 sig digits ROUND_HALF_EVEN, pinned, not
per-call-overridable; exact halving for midpoints. Absent-vs-zero defined (price-derived
features ABSENT on empty sides, sums report "0", typed per-quantity INSUFFICIENT_DEPTH).
Book state enters only as serializeBook v1 text (`polymarket-bot/order-book/v1`), the
reader bound to the real writer by cross-tests over live `OutcomeTokenBook` instances —
no second canonical form. Zero runtime schema library: inputs materialized prototype-free
before hand-rolled total validation. Time enters only as strict-UTC event timestamps under
pure calendar arithmetic — no `Date` surface in production sources.
`docs/contracts/features-v1.md` is the normative contract.

## known_risks

- **R1-L1 (LOW, carried)**: `docs/contracts/features-v1.md:140` overclaims "one instant,
  one spelling, one address" — the timestamp grammar (`time.ts:33`) accepts 0-3 fractional
  digits including trailing zeros, so up to four spellings of one instant are each accepted
  and produce DISTINCT content addresses. Determinism (same input value → same address)
  holds; address-based dedupe of logically identical inputs will miss. Fix: correct the
  contract text (doc-only), or tighten the grammar under the §8 version-bump rule.
- **R1-L2 (LOW, carried)**: `validateFeatureInput` (`inputs.ts:686-690`, exported) documents
  "never throws" but a throwing enumerable getter on a NON-materialized tree escapes; the
  composed entry `computeFeatureSnapshot` is genuinely total (materializes first + contains).
  Hazard is a downstream caller (e.g. WP-220/WP-230) invoking the validator directly on raw
  input. Fix: state the materialized-tree precondition, or wrap the export in the same
  totality guard.
- **R1-L3 (LOW, carried — the substantive one)**: `selectIndexedValues` members
  (`snapshot.ts:430-442`) are ordinary literals, NOT prototype-free — under
  `Object.prototype` pollution an absent optional field reads the polluted value (measured
  adoption), the exact output-side class the package eliminates everywhere else. These
  values are destined for PostgreSQL indexing next to decisions (§9.5). Fix: route members
  through the existing `ownFrozenTree`/`ownPlainCopy` machinery. Owner: next bounded
  package touching `packages/features/**`, or a dedicated WP-160-FU1 if a consumer lands
  first; ALSO recorded as corroborating input to the schema-boundary governance round.
- **R1-N1**: `node:crypto` in a layer-1 package (`hash.ts:14`; pure synchronous SHA-256, no
  entropy/clock/I/O) — third instance of the layer-1 Node-built-in contract question
  (WP-180 R6-1 `node:util` in risk/capital-allocator/execution-planner). For the
  governance round's allowlist ruling; a future F-row binding features' import surface
  would close it mechanically.
- **R1-N2**: ambient `Array.prototype` index pollution fails CLOSED (typed
  `FEATURES_INPUT_NOT_DATA` refusal, no throw) — availability under ambient pollution
  sacrificed to correctness, consistent with the disclosed divDecimal-options posture.
- **R1-N3**: the shipped wall-clock source scan is regex-based and dodgeable in principle
  (aliasing, dynamic import) — compensated today by the reviewer's independent grep (zero
  clock surface) and the fake-timer behavioral probe; same class as WP-180 R9-1
  (indirection detector), for the governance round.
- Implementer known_risk (carried to the governance round): layer-0 `divDecimal` with
  EXPLICIT `DivisionOptions` calls `Decimal.clone` per invocation and throws under an
  inherited get-only `Object.prototype.set` — unreachable from this package, but reaches
  every explicit-options caller repo-wide.
