# WP-060-FU1 completion record — The packages/event-bus envelope own-data door

**Merged:** `d869868` (`--no-ff`, 2026-09-11). Chain on base `cda7119`:
`16c0072` (candidate) → `22ed002` (r1) → `3c7f477` (r2) → `04c7bc9` (r3) →
`d99c2ac` (r4). Review arc: r1 **CHANGES REQUIRED** (2 blockers) → r2, r3 and
r4 each opened by an independent review finding → **CONFIRMED ACCEPT**. Four
remediation rounds, every one of them opened by a reviewer rather than by the
implementer.

**What it is.** The last §5-follow-on grant named by the `schema-boundary.md`
§3 `packages/event-bus` row. At base, `validateEnvelope` threw
`EventBusEnvelopeError` on honest-but-invalid input, but under an inherited
non-enumerable `skipChecks` an envelope with `eventId: "not-a-uuid"` and
`receivedAt: "yesterday"` was ACCEPTED, and the function returned the
CALLER'S OWN OBJECT. The round installs the ADR-020 door: materialize the
caller's own enumerable data into a null-prototype tree before parsing,
judge that copy inside containment, re-check every field against
constraints derived from the schema's own `_zod.def` by own-property reads,
and emit a frozen prototype-free record.

## The review arc (three rounds, each earned)

- **r1 (CHANGES REQUIRED, 2 blockers).** **B1**: the candidate re-enforced
  only the 4 ordering fields, but an inherited `skipChecks` disables EVERY
  zod check, so the other 13 fields and the source/venue provenance
  refinement were still fail-open. **B2**: the containment's own fallback
  `EventBusEnvelopeError` read an inherited `options.cause` via the `in`
  operator, so a throwing inherited `cause` accessor escaped as a bare
  `TypeError`. Everything else verified positive.
- **`22ed002` (r1 remediation).** Derivation generalized to all 17 fields
  from `_zod.def` (patterns, length and numeric bounds, safeint, enum,
  optional) by own-property traversal with no mirrored literals; the sole
  refinement re-stated on own data; `errors.ts` switched to
  `Object.hasOwn(options, "cause")`.
- **r2 finding (MEDIUM).** The output contract changed from the caller's
  object to a frozen null-prototype record, and vitest's `toStrictEqual`
  compares constructors at every level. Four assertions in
  `test/integration/event-bus/round-trip.test.ts` therefore failed at the
  tip and passed at base — in a Docker-gated suite that no reproduced gate
  could run at the time, so the finding came from a static read plus a
  tip-vs-base assertion-shape probe. It was confirmed by execution later
  (see Residuals).
- **`3c7f477` (r2).** Those four sites now assert value equality plus the
  contract itself: not the published object, frozen, null prototype, and
  `JSON.stringify` byte equality at the whole-envelope site. Inside
  `WP-060`'s ratified `allowed_paths`.
- **r3 findings.** One MEDIUM: the door correctly refuses a missing
  required field while zod's required-key waiver is inherited, but nothing
  pinned it in either prototype form, and a one-line regression reopened it
  with the suite fully green. Four LOW: the non-plain-prototype,
  function/symbol, sparse-array, symbol-key and unknown-key refusals each
  survived deliberate removal untested. Two LOW on drift: the module
  advertises fail-closed-on-drift, but three schema shapes loaded silently
  with a non-equivalent predicate.
- **`04c7bc9` (r3).** Three new test files (37 tests) and four load-time
  guards. Every listed regression is now killed by a named test.
- **r4 finding (CRITICAL) — the one that mattered most.** `encodeEnvelope`
  ended in `JSON.stringify`, which looks `toJSON` up through the value's
  PROTOTYPE CHAIN. The materialized objects are null-prototype and were
  immune, but the materialized ARRAYS deliberately keep `Array.prototype`,
  whose own chain reaches `Object.prototype`. With an inherited `toJSON`
  installed, an ACCEPTED envelope carrying an array payload encoded as
  `"payload":"INJECTED"` — wrong bytes on the wire with no change of verdict,
  reproduced in both prototype forms and confirmed independently by the
  orchestrator. The previously disclosed "arrays keep `Array.prototype`"
  NOTE was therefore not benign: it had a concrete wrong-value instance.
- **`d99c2ac` (r4).** The bytes now come from `encodeWireJson`, an own-data
  restatement of `JSON.stringify` (ECMA-262 25.5.2) that never consults a
  prototype. While building it the implementer found a SECOND route the
  review had missed, and a worse one: `SerializeJSONProperty` also looks
  `toJSON` up for a value of type **BigInt**, and that lookup walks
  `BigInt.prototype` → `Object.prototype`, so a payload containing a bigint
  went from a typed refusal to ACCEPTED with substituted bytes — a VERDICT
  flip, not just a byte flip. Both routes are closed. Containment also stopped
  using `instanceof` (which walks a chain a Proxy can hijack, and did: a bare
  `RangeError` escaped the boundary) in favour of an own-data brand read
  through one descriptor lookup inside a guard; BOTH classification sites
  needed it, not the one the reviewer named. `decodeEnvelope` now refuses a
  non-string with a typed refusal.

## What the reviews proved positive

- **Both original blockers closed** (Codex, independent): 61 invalid inputs
  × 3 ambient states = 183 typed refusals covering all 17 fields; all 10
  required-field deletions refused in six cold contexts (`optin`, `optout`,
  and both together, each enumerable and non-enumerable); 618 honest-input
  comparisons with exact JSON equality; 70 containment checks (seven
  raising accessor names × two enumerability modes × five refusal paths)
  every one yielding `EventBusEnvelopeError`.
- **Neither fail-open nor stricter than the schema** on the field level: a
  9,197-row per-field differential of the derived predicates against
  `schema.shape[key].safeParse` found **zero** divergence in either
  direction.
- **The output contract is safe for every consumer.** The only call sites
  are `redis/transport.ts` (publish), `redis/subscription.ts` (decode) and
  `testing/container.ts`; no consumer relies on envelope identity,
  prototype or mutability; all 22 registered event samples survive
  encode → decode → `DOMAIN_EVENT_REGISTRY.parseEnvelope`; zod accepts the
  null-prototype frozen record; the trader's own door re-materializes it
  through `readPlainData`, which accepts a null prototype.
- **Wire bytes unchanged and now ambient-independent**: the six pinned
  fixtures and a 1.4 MB book-like payload encode byte-identically to base,
  and the orchestrator's own adversarial corpus of **11,335 materialized
  trees** (every code unit to 0x23FF, all lone surrogates, astral pairs, C0
  controls, quotes and backslashes, 5,000-character strings, −0, 1e21, 1e-7,
  denormals, 2**53, `undefined`-valued keys nested and top level) found
  **zero** differences against `JSON.stringify` in a clean environment, with
  identical bytes across all six pollution contexts
  (`Object.prototype` / `Array.prototype` / both × enumerable and
  non-enumerable).
- **The required-key waiver mechanic was corrected by measurement**: it
  needs `optin` AND `optout` inherited together; either alone does not
  waive. Both the implementer and the independent reviewer established this
  separately.

## Sanctioned tightening

zod's strict-object unknown-key scan deliberately skips a top-level own
`__proto__` member, so the schema ACCEPTS a wire envelope carrying
`"__proto__": …` and silently drops it. The door's unknown-key restatement
is the only layer that still sees the member, and it refuses. Silent
dropping on the recording path is what §8.3 forbids, so this divergence
from the schema's verdict is deliberate. It is commented at the check site
and pinned by name in `envelope-data-refusals.test.ts` so a future reader
does not "fix" it back.

## Residuals (owned)

- ~~The Redis integration suite was never executed.~~ **CLOSED before
  merge**: Docker became available and the suite was run at the merged tip —
  **81 / 81 passing, 8 files**. It was also run at `22ed002` (before r2) as
  a control, where it failed in exactly the four predicted places
  (`round-trip.test.ts` lines 46, 62, 95 and 113, each "expected … to
  strictly equal …") with the other 77 tests passing. That converts the r2
  finding from a static prediction into a measured one and shows r2 fixed
  precisely those four sites and nothing else.
- **`redis/transport.ts` keys the epoch queue, ordering guard and cursor on
  the caller's object** while the wire bytes come from the door record, so
  a Proxy caller could make the in-process ordering decision disagree with
  what was written. No such producer exists (the sole path is zod output,
  and the door refuses accessors), the pattern is byte-identical to base,
  and `transport.ts` has no unit test at all — its only coverage is the
  Redis integration suite. Deliberately left untouched: the acceptance bar
  treats a shape with no concrete instance as a disclosed residual, and
  widening a round that had already taken three remediation passes would
  have bought a fourth review cycle for a defect nothing can reach. **Owner:
  a bounded follow-up round, which should pass the validated record to the
  ordering path and add unit coverage for `transport.ts`. Docker is now
  available on this host, so that round can be validated end to end.**
- **Cost.** The door deep-copies, redefines and freezes every payload node
  on both the publish and the decode path, where the base parse never
  walked the opaque payload. Measured linear at roughly 75–100 ns per
  serialized byte: 3–4× on the largest honest fixture (522 B), ~20× on a
  1.2 MB payload, and ~545 ms synchronously for a 7.1 MB one, against the
  publisher's 8 MiB admission bound. No super-linear route exists.
  **Owner: operator soak/profiling; never claimed as measured in
  production.**
- **New fail-closed refusals** relative to base, all availability-only and
  none reachable from an honest producer: payload nesting 16+ object levels
  (deepest registered payload is 3); and payload members that are a `Date`,
  `Map`, class instance, boxed `String`, accessor, sparse array, symbol key,
  function or symbol — the `z.unknown()` payload schema accepted these, and
  at base a `Date` encoded as its ISO string. Now pinned as deliberate.
- **`encodeWireJson` is a hand-written restatement of `JSON.stringify`.**
  Its guard is a differential over a generated corpus — 10,928 trees by the
  implementer, 11,335 by the orchestrator and 198,733 by the confirming
  reviewer, all with zero byte differences. Any future value shape the door
  begins to materialize must be added to that corpus. One documented
  behavioural difference: a bare `undefined` root raises a typed refusal
  where `JSON.stringify` returns `undefined`; unreachable through
  `encodeEnvelope`, whose argument is always the materialized record.
- **Brands are classification safety, not authenticity.** A caller already
  holding a genuine refusal could copy the private symbol off it. The
  confirming reviewer judged this equal in forgeability to the
  `instanceof` test it replaces (`Object.create(Error.prototype)`) and
  strictly stronger against throwing reflection traps. Recorded in
  `brand.ts`.
- **Disclosed ADR-020 classes**, unchanged by this round: arrays retain
  `Array.prototype` (no instance found), and the severed warmed arena (D2)
  is not performed — the shared arena is not importable on this package's
  dependency edges.
- **`envelope-fixtures.ts` pins zod issue-message strings verbatim**, so the
  ADR-020 §7 zod upgrade gate now also trips on a wording change rather
  than only a behaviour change. Intended, recorded.
- **The `22ed002` commit message says "Five honest encodeEnvelope
  captures"** while the tree pins six fixtures. The substantive claim holds
  (all six are byte-pinned and green); the number is wrong and history was
  not rewritten.
