## summary

Verified current official Polymarket integration behavior against official
sources (all accessed 2026-08-24) and froze three deliverables, without
placing any order, loading any credential/signer, or making any
authenticated call:

1. **Verification report** `docs/venue/verified-2026-08-24.md` — every venue
   statement cites its official source with access date. Rules the unified
   SDK `@polymarket/client` (Node `>=24`) as the only permitted client and
   explicitly REJECTS archived CLOB/relayer/builder-signing clients. Covers
   order schemas and GTC/GTD/FOK/FAK expiration rules, delayed/unmatched
   responses, market and user WebSocket schemas (raw SDK wire layer vs
   normalized docs layer, frozen against `Polymarket/ts-sdk` reference
   commit `7fdbed42484b5d279c71aa36d3757d18968260da`), heartbeat protocol
   (empty-ID bootstrap, per-response ID rotation, 5 s cadence / 10 s
   timeout / 5 s cancellation sweep), fees and maker/taker/liquidity reward
   snapshots, per-market parameters (dynamic tick size, min size, negRisk,
   secondsDelay), IP and per-signer rate limits as configuration snapshots
   (all eight signer tiers; exact per-endpoint dual limits), matching-engine
   restricted modes (HTTP 425 restart with undocumented body; 503
   cancel-only/post-only with `error`/`code`/`retry_after_seconds` and
   `Retry-After`), geoblock, CTF split/merge/redeem with published Polygon
   contract addresses and `TransactionOutcome` handles, and Chainlink TWAP
   over RTDS (30 s/60 s, no replay after disconnect). Conflicts C-1..C-4
   and UNVERIFIED items U-1..U-9 (U-5, U-8 resolved) are explicit.
2. **Sanitized fixtures** `test/fixtures/venue/**` (16 JSON files + README
   with provenance and sanitization rules): market WS events (book,
   price-change incl. flagged zero-size removal, tick-size change, last
   trade, best bid/ask, lifecycle), raw user WS order lifecycle and trade
   settlement per the SDK raw schemas, REST trades with prefixed
   `TRADE_STATUS_*` constants (REST-only `MATCHED_NOT_BROADCASTED`), order
   placement responses incl. delayed and failure shapes, restricted modes,
   heartbeat rotation, fee/reward snapshots, rate-limit headers/tiers,
   geoblock, split/merge/redeem, RTDS TWAP.
3. **Verification CLI skeleton** `apps/ops-cli/src/verify-venue/`
   (`checks.ts`, `fixtures.ts`, `index.ts`, `fixtures.test.ts`): enumerates
   the handoff §1.2 checks; validates fixtures against source-specific,
   recursively nested schemas (types, enums, optionality, canonical
   decimals per §7.3, prices bounded to [0,1]); scans for credential-shaped
   keys (case/separator-insensitive, incl. `POLY_API_KEY`,
   `POLY_PASSPHRASE`, `POLY_SIGNATURE`, `POLY_ADDRESS`,
   `SIGNER_PRIVATE_KEY`, owner fields); validates the frozen report
   (existence, required sections, per-section official evidence,
   official-domain citations); reports PASS/FAIL/DOCUMENTED with no vacuous
   passes; exposes formatter and exit-code mapping. Never touches the
   network; never requires credentials. NOT wired into the CLI entry point
   (outside allowed paths; owned integration plan in report §15).
