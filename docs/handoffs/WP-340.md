## WP340-F1 (found, deferred, ruled)

A `LIVE` order event that reaches WP-270's OMS after the OMS holds the order FILLED or CANCELED raises a halting `EVIDENCE_CONFLICT`. WP-290 then quarantines the market, and the account stays paused until an operator releases it. Safety holds; liveness does not.

It has three routes, one of them fault-free: the OMS places and cancels an order faster than the user stream pushes its `PLACEMENT`.
- **The pins:** four `it.fails` pins in `findings.test.ts` state the wanted behaviour, and four "TODAY" tests pin the current one.
- **The recovery driver:** it releases only the exact F1 signature. Round 1's HIGH, J1, was an over-broad driver; it was fixed and mutation-pinned.

**Disposition:**
- **The orchestrator deferred the fix out of this package,** since it needs product code in `packages/oms`.
- **The user ruled venue-time ordering (2026-10-05).** The venue timestamp goes into the OMS. A `LIVE` older than the terminal evidence is stale; a newer one still halts.
- **Next:** a pre-live ADR, then an OMS round (the brief's `WP340-F1` row).
