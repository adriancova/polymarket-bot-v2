## summary

- **WP300B-R1-01.** Every field of every observation, reconciliation answer and executor answer is read exactly once, at the door, before any decision. So a Proxy whose value changes between reads can no longer conclude an operation.
- **WP300B-R1-02.** A field that is present but is not own data, meaning a getter, an inherited property or a read that throws, makes the evidence unrecognised. It never counts as "names no request" or "names nothing".
- **WP300B-R1-03.** The manager's header carries a REFUSAL CODES table, state × answer shape. `refusal-codes.test.ts` parses it and checks every cell against the code.
- **WP300B-R1-04.** The `fetch` tripwire is a vitest setup file, installed before each test module loads, and it is load-bearing. `network-tripwire.test.ts` runs the suite's config over six planted files in a child process. Each planted fetch must fail the suite with the tripwire's own message: swallowed at load, from a microtask, in a test, in `afterAll`, and uncaught. A clean control must pass.
- **Predictable request ids.**
  - Answers bind only to requests the reconciler actually received, judged from the start of the answer's read. An id named before receipt is never bound, so a verbatim replay is refused too, and the operation gets a replacement request.
  - The held-back read of a predicted id (`WP300C-J1`) is defeated by an **unguessable request token**. Ids are `compositeKey("wallet-op", operationId, "reconciliation", n, token)`.
  - The token comes from a required injected `requestToken: () => string`: at most `MAX_REQUEST_TOKEN_LENGTH` (128) characters, non-empty, never repeated.
  - The composition must bind `requestToken` to a CSPRNG.

## known_risks
- **The token source.** It must be a CSPRNG in the composition. A predictable source re-opens J1. A source that keeps failing stalls reconciliation with the reservations held: safe, but silent.
- **Reproducibility.** Ids are not reproducible across runs. A journal or replay must record the drawn tokens.
- **WP-290 obligations.** It must echo `requestId`, and never answer with a read made before receiving the request. No id scheme can detect such a read.
- **WP300C-J9 (INFO).** The tripwire traps `fetch` only; Node 24's global `WebSocket` is not trapped.
- **R4-01 and R4-02 (INFO).** Some header prose still says "not issued", and one test-header sentence overstates which controls pass on base.
- **`WP300-PERSIST` is unchanged.** Persist or bound the named-id, token and receipt records.
