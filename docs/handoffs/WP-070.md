## summary

`packages/polymarket-public` replaces its `WP-010` placeholder with the public,
unauthenticated Polymarket market-data adapter: the market WebSocket client and
its subscription manager, the REST book-snapshot fetcher, and the normalization
of both into the frozen domain events.

### 1. C-1 / U-1 is CONFIRMED, and flagged for ratification

The acceptance criterion required confirmation against current official sources
or an ADR-governed flag. **It is confirmed.** Details and verbatim quotes are in
[`assumptions`](#assumptions) §1 and in `packages/polymarket-public/README.md`
§2. In one line: the current Market Channel API reference states that
`price_change.size` is the **"New aggregate size (0 means level removed)"**.

The provisional labelling elsewhere in the repository is **left in place**,
because every file carrying it is protected or owned by another package, and
because ratifying the register entry is an orchestrator/ADR step, not this
package's. See [`follow_up`](#follow_up) item 1.

### 2. The wire layer, anchored to the SDK rather than transcribed on trust

`src/venue/` carries the seven market-channel event schemas plus the REST book
schema, transcribed from `Polymarket/ts-sdk` at the pinned reference commit
`7fdbed42484b5d279c71aa36d3757d18968260da`. Register item **R-2** required that
the transcription not be silently load-bearing; the mechanism is described in
[`assumptions`](#assumptions) §2 and is 116 executing assertions in
`test/contract/polymarket-public/sdk-anchor/`.

The adapter does **not** import `@polymarket/client` (F6) or any archived client
(F7). Node 24's own `WebSocket` and `fetch` are used directly, so the package
declares no venue dependency at all.

### 3. The venue edge does its job

Every ADR-001 §8 / ADR-002 §7 obligation is discharged in the adapter, not
pushed at the domain boundary:

- `""`, `null`, and an absent key collapse to **absent**; an absent best bid is
  never turned into `"0"`.
- Venue decimal spellings are canonicalized through `@polymarket-bot/decimal` —
  the same implementation the domain schemas validate against. The wire is
  demonstrably non-canonical (`"last_trade_price": "0.090"` in the venue's own
  example).
- Every epoch-like form the SDK accepts is accepted, including the date-like
  string.
- An unrecognized free-string value is first-class **UNKNOWN**, reported with
  the raw frame attached.
- A 31-byte (or any other length) hex condition id is accepted; the fixture
  catalogue's 31/32-byte bound is not inherited.

Every payload is then parsed by its own domain contract before it is emitted; a
failure becomes a `PAYLOAD_CONTRACT_VIOLATION` problem rather than a malformed
document downstream.

### 4. Nothing is dropped, and no sequence number is invented

Every element of every inbound frame becomes **exactly one** normalized event or
**exactly one** `PublicMarketProblem` carrying the raw value (§8.3). The
contract suite asserts that accounting on a mixed frame. Normalized events carry
no sequence field: ordering is `(gatewayEpoch, ingestSeq)`, which the gateway
assigns (§9.4, ADR-002 §2.3).

### 5. Tick-size changes are emitted exactly

One `TradingParametersChanged` per `tick_size_change`, `changedParameters`
exactly `["tick_size"]`, `tickSize` the canonicalized `new_tick_size` and
nothing else — and the `tick_size` field that rides on a `book` snapshot never
produces one, because a snapshot restates a parameter rather than announcing a
change.

### 6. Feed health is data

`FeedConnected`, `FeedDisconnected`, `FeedStale`, `FeedGapDetected`, and
`FeedResynchronized` are emitted on the same stream as the market data. A
reconnection or a subscription change opens a gap with
`requiresAuthoritativeSnapshot: true`; `FeedResynchronized` is **caller-driven
only**, because reopening a socket is not a recovery and this adapter cannot
observe that a snapshot was applied.

### 7. Three deliberate silences, each with its evidence

- `price_change.hash` is not emitted as `BookLevelChanged.venueBookHash`: the
  venue documents it as the "Hash of the order that caused this change", while
  `book.hash` is the "Hash of the orderbook content".
- `last_trade_price.transaction_hash` is not emitted as
  `PublicTradeObserved.venueTradeId`: one settlement transaction can carry
  several trades, so it would silently deduplicate distinct ones.
- `price_change.best_bid`/`best_ask` do not produce a second
  `BestBidAskChanged`: the venue has a dedicated top-of-book event, and a rival
  synthesized stream would leave two contradictory histories.

## assumptions

### 1. C-1 / U-1: CONFIRMED against current official sources (2026-08-27)

The workplan criterion, verbatim: "Book price-change semantics (C-1/U-1
absolute-size zero-removal) are confirmed against current official sources or
recorded observation; on confirmation the provisional rule is ratified,
otherwise the affected contracts are flagged for an ADR-governed revision. The
provisional behavior is never asserted as settled without this evidence."

**Outcome: confirmed by documentation, not by observation.** No live connection
was made and no observational claim is made anywhere.

**What changed since 2026-08-24.** The URL the frozen report cites,
`https://docs.polymarket.com/market-data/websocket/market-channel`, now redirects
(HTTP 200 after redirect) to
`https://docs.polymarket.com/market-data/realtime-data#market-stream`. That page
still does not state the semantics. A **new** page not in the frozen report's
source index does:
`https://docs.polymarket.com/api-reference/wss/market` ("Market Channel — Public
WebSocket for real-time orderbook, price, and market lifecycle updates"),
published as an AsyncAPI document and also served as
`.../api-reference/wss/market.md`. All quotes below are from that page,
retrieved read-only and unauthenticated on **2026-08-27**.

Verbatim, from the `price_change` message definition:

> `size` — `New aggregate size (0 means level removed)`

> `price` — `Price level affected`

> `hash` — `Hash of the order that caused this change`

> `timestamp` — `Unix timestamp in milliseconds`

Verbatim, the operation and payload descriptions:

> `Delta update to orderbook price levels when an order is placed or cancelled`

> `Orderbook price level delta update`

Verbatim, from the `book` message definition, corroborating the aggregate
reading:

> `Full orderbook snapshot sent on subscribe or after a trade`

> `bids` — `Aggregated buy orders by price level`; `size` — `Total size at this price level`

> `hash` — `Hash of the orderbook content`

**Reading.** The *message* is a delta — it reports only the levels that changed —
while the `size` it carries is the new **aggregate** size at that level, and `0`
removes the level. That is exactly the handoff §23 assumption `WP-000` retained
provisionally. `BookLevelChanged.size` therefore carries the venue value through
unchanged, `"0"` included, and no delta arithmetic exists anywhere in this
package.

Two corroborating quotes retrieved the same day:

- `https://docs.polymarket.com/market-data/prices-order-books`: "Bids are ordered
  by ascending price and asks by descending price, so the best bid and ask are
  the last entries in their respective arrays. Each response also includes a
  `hash` for the order-book state. Compare it with the previous response's hash
  to determine whether the book changed between reads."
- `https://docs.polymarket.com/market-data/realtime-data`: the market WebSocket
  address, the `assets_ids`/`type: "market"` subscribe frame, the
  `custom_feature_enabled` flag, the dynamic subscribe/unsubscribe frames, and
  "Send the text frame `PING` every 10 seconds; the server replies with `PONG`".

**What this package did NOT do.** It did not edit
`packages/domain/src/events/book.ts` (protected), did not edit
`docs/contracts/protected-contracts.md` §8 (protected), did not edit ADR-002 §8
(protected), and did not rename the `WP-000` fixture example
`level-removed-absolute-zero-UNVERIFIED` (`test/fixtures/venue/**` is not in this
packet's allowed paths, and a frozen fixture catalogue is not an implementer's to
relabel). The confirmation is therefore **flagged for orchestrator/ADR
ratification** — [`follow_up`](#follow_up) item 1 — and until that lands the
repository still says "provisional" in those four places. Nothing in this package
asserts the semantics are settled on its own authority; every statement of them
carries the source, the quote, and the retrieval date.

### 2. R-2 anchoring: how it works

Register item R-2 (`docs/contracts/protected-contracts.md` §8.1) is assigned to
this packet "for the venue-adjacent schemas it owns". The concern is that a hand
transcription of an SDK schema is a silent verification error when nobody checks
it.

**The mechanism is `test/contract/polymarket-public/sdk-anchor/`.** The anchor
table records, for every field of every venue schema this package owns, the
modifier the official SDK declares for it (`required`, `literal`, `.nullish()`,
`z.array(...).nullish()`, or `OptionalDecimalStringSchema`), together with a
commit permalink into the pinned reference commit. `anchor.test.ts` then makes
each row executable, in five ways:

1. **Field-set equality, both directions.** Every key of the package's zod schema
   must appear in the table, and every table row must appear in the schema. The
   schema's key list is read at runtime from `schema.shape`, so it cannot drift
   from a copy.
2. **Field count against the SDK.** Each anchor carries `sdkFieldCount`, the
   number counted in the SDK source at the pinned commit on 2026-08-27. Adding a
   field to both the schema and the table without re-reading the SDK changes the
   count and fails, which forces the re-read to be recorded rather than assumed.
3. **Accept/reject vectors per modifier, through the real entry point.** A
   `required` field must make the event fail when omitted and pass when present;
   a `.nullish()` field must accept `null` **and** absence; an
   `OptionalDecimalStringSchema` field must additionally accept the wire empty
   string; a `literal` must reject a foreign value. A modifier transcribed
   wrongly changes observable behaviour and fails. Nested schemas are driven
   through their parent event, so the test exercises the same code path
   production does.
4. **Citation hygiene.** Every anchor and every field citation must embed the
   pinned commit; a mutable `blob/main` link is rejected, so a later SDK change
   cannot silently invalidate a citation.
5. **Recorded divergences.** Where this package is deliberately looser than the
   SDK, the row must carry a written `sdkDivergence` reason. A divergence with no
   reason is indistinguishable from a transcription mistake, which is exactly
   what R-2 is about.

116 assertions run from that table. Five recorded divergences, all on the REST
book schema and all in the "accept more" direction: the SDK's 40-hex `hash`
(the venue's own API example prints 64), its 31/32-byte `market` bound (ADR-002
§7 forbids inheriting it), its `tick_size` conversion to a float literal
(ADR-001 forbids a float for an economic value), and `min_order_size`/`neg_risk`
which the SDK's REST schema requires while the SDK's own WebSocket book event
marks them optional.

**This does not close R-2 for the repository** — `WP-000`'s `checks.ts` is a
different package's transcription and is untouched here. It closes it for the
schemas this packet owns, which is what the register assigns.

### 3. Venue-fact assumptions (all cited, none invented)

- The market channel may deliver a **single event object or a JSON array of
  them** in one text frame. Basis: the official SDK's own market socket branches
  on `Array.isArray(message)` before dispatching
  (`packages/client/src/websockets/clob/market.ts` at the pinned commit). A
  client assuming one event per frame would lose every event after the first.
- `last_trade_price.side` is the **taker's** side. Basis: the API reference types
  it `BUY | SELL` and describes it "From taker's perspective". That is what
  licenses mapping it onto `PublicTradeObserved.takerSide`; `BUY → BID`,
  `SELL → ASK`.
- The `level` subscription field (`1 | 2 | 3`, default `2`) exists, and the
  reference documents no meaning for the three values. This package therefore
  **never sends it** and lets the server default apply.
- **U-2 remains unknown.** No server-side timeout or close code for a missed
  `PING` is published. The client measures only its own side; the 30 s default is
  the SDK's `CLOB_HEARTBEAT_STALE_MS`, evidence of what the SDK treats as dead,
  not of a server rule.
- **U-3 remains unknown.** No maximum `assets_ids` per subscription is published.
  No cap is imposed by default, and that is explicitly not a claim that none
  exists; `maximumAssetsPerSubscriptionFrame` exists so an operator can apply the
  real bound when it is known.

### 4. Architectural assumptions

- **The gateway envelopes; the adapter normalizes.** Normalized events carry
  `(eventType, schemaVersion, payload)` plus venue-supplied provenance and
  nothing else. `observedIndex` orders events *within one frame* only and is
  never a persisted ordinal.
- **Identity and versioning belong to the catalogue.** `InternalMarketId`, the
  YES/NO token assignment, `metadataVersion`, `parametersVersion` and
  `parameterVersionRef` all arrive through the `PublicMarketDirectory` port. A
  declined answer becomes a reported problem. In particular the adapter does
  **not** pair `assets_ids` with `outcomes` by index: the venue publishes two
  parallel arrays and documents no pairing rule.
- **`MarketResolved` is decided by the winning token**, compared against the
  catalogue's two outcome tokens, not by the free-text `winning_outcome` label.
  A resolution naming no winner is reported (`MISSING_WINNING_TOKEN`), never
  guessed at as a 50/50 — U-6 is still open.

## deviations

1. **A `README.md` was added to the package.** The packet asked for the C-1/U-1
   evidence to be recorded "in your package contract documentation"; the package
   had none, and `docs/contracts/**` is protected. `packages/polymarket-public/README.md`
   is inside the allowed paths and is that documentation.
2. **A REST book fixture is owned by this suite, not by `test/fixtures/venue/`.**
   `WP-000` froze no order-book REST examples and `test/fixtures/venue/**` is
   outside this packet's allowed paths, so
   `test/contract/polymarket-public/fixtures/clob-book-rest.json` carries the
   same provenance envelope (source URL, retrieval date, sanitized flag,
   provenance note) and is explicitly marked as not part of the frozen `WP-000`
   catalogue.
3. **The REST wire schema is deliberately looser than the SDK's in five places**,
   all recorded with reasons in the anchor table and in
   `src/venue/order-book.ts`. Two are ADR-mandated (the condition-id bound, the
   float tick size), one is forced by the venue's own contradictory published
   hash lengths, and two align the REST book with the WebSocket book event.
4. **`price_change.best_bid`/`best_ask` produce no `BestBidAskChanged`**, and
   `last_trade_price.transaction_hash` is not carried as `venueTradeId`. Both are
   deliberate non-emissions with recorded reasons (see [`summary`](#summary) §7);
   both drop a venue field from the normalized stream, and the raw frame is
   preserved by the recorder. Recorded here because a reviewer should challenge
   them rather than discover them.
5. **`PublicMarketDirectory` is a new port.** Emitting `TradingParametersChanged`,
   `MarketDiscovered`, or any book event at all requires an `InternalMarketId`
   the adapter must not mint. The port is three methods wide and every one may
   decline. It is a seam `WP-110`/`WP-120` must implement; it is not a redesign
   of the catalogue.
6. **No RTDS subtree exists.** `packages/polymarket-public/src/rtds/**` belongs to
   `WP-100` and was neither created nor designed, per the packet.

   `follow_up` 1 should record "confirmed by documentation on 2026-08-27" rather
   than "verified".
2. **The frozen venue report is drifting.** The URL it cites for the market
   channel now redirects, and the page it redirects to publishes a *normalized*
   SDK event shape (`topic`/`type`/`payload`, `tokenId`, ISO timestamps)
   alongside the raw wire shape in its API tab. The raw shape still matches the
   frozen fixtures exactly. A future phase gate should re-issue the report with
   the new URL; nothing in this package depends on the old one.
3. **The venue's published `hash` length for a REST book is self-contradictory**
   (40 characters in the TypeScript tab, 64 in the API tab, for the same field).
   This package pins neither and compares the value only for equality, which is
   what the page says it is for. A consumer that assumed SHA-1 would be wrong
   half the time.
4. **Gap detection is connection-level, not message-level.** With no venue
   sequence number, a *silently missed message on a healthy connection* is
   undetectable by any client, and this package invents nothing to paper over it.
   What it detects — reconnects, subscription replacement, heartbeat staleness —
   is what §7.1 actually turns on. `WP-150` should not read the absence of
   `FeedGapDetected` as proof that no message was missed.
5. **`observedIndex` is easy to misread.** It orders events within one frame and
   nothing more. A consumer that persisted it as an ordinal, or compared it
   across frames, would have invented the sequence number §9.4 forbids. It is
   documented as such in three places, but it is a foot-gun.
6. **`PublicMarketDirectory` is unimplemented.** Until `WP-110` provides a real
   catalogue, every market event normalizes to an `UNRESOLVED_MARKET` problem.
   That is the honest behaviour, but it means an integration built on this
   package before `WP-110` will see problems, not events.
7. **Batch snapshot fetches are sequential.** The venue publishes per-endpoint
   rate limits as a volatile configuration snapshot this package does not model,
   so a recovery over many markets is slower than a fan-out would be. The
   alternative — an unbounded parallel burst on the recovery path — is how a gap
   becomes a throttled gap. Rate-limit-aware scheduling is `WP-310`'s.
8. **The staleness default is borrowed.** 30 s comes from the SDK's own
   client-side constant, not from any published server behaviour (U-2). A feed
   whose real server timeout is shorter would be closed by the server before this
   client notices; the reconnect path handles that, but the `FeedStale` event
   would not precede it.
9. **`markResynchronized()` is an assertion the caller makes.** The adapter
   cannot verify that a snapshot was applied. A caller that called it without
   applying one would publish a `FeedResynchronized` claiming a recovery that did
   not happen — the one hole the contract's pinned literal cannot close, because
   it is a caller-side lie rather than a representable document.
10. **`test/contract/polymarket-public/**` is not wired into any root script.**
    It runs from the package's `test:contract` script only. Root wiring is
    orchestrator-owned at merge (`follow_up` 3).
