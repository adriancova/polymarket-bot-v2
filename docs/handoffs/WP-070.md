## summary

`packages/polymarket-public` replaces its `WP-010` placeholder with the public,
unauthenticated Polymarket market-data adapter: the market WebSocket client and
its subscription manager, the REST book-snapshot fetcher, and the normalization
of both into the frozen domain events.

### 1. C-1 / U-1 is CONFIRMED, and flagged for ratification

The acceptance criterion required confirmation against current official sources
or an ADR-governed flag. **It is confirmed.** Details and verbatim quotes are in
[`assumptions`](#assumptions) §1 and in `packages/polymarket-public/README.md`
§2. In one line: the current Market Channel API reference states that
`price_change.size` is the **"New aggregate size (0 means level removed)"**.

The provisional labelling elsewhere in the repository is **left in place**,
because every file carrying it is protected or owned by another package, and
because ratifying the register entry is an orchestrator/ADR step, not this
package's. See [`follow_up`](#follow_up) item 1.

### 2. The wire layer, anchored to the SDK rather than transcribed on trust

`src/venue/` carries the seven market-channel event schemas plus the REST book
schema, transcribed from `Polymarket/ts-sdk` at the pinned reference commit
`7fdbed42484b5d279c71aa36d3757d18968260da`. Register item **R-2** required that
the transcription not be silently load-bearing; the mechanism is described in
[`assumptions`](#assumptions) §2 and is 116 executing assertions in
`test/contract/polymarket-public/sdk-anchor/`.

The adapter does **not** import `@polymarket/client` (F6) or any archived client
(F7). Node 24's own `WebSocket` and `fetch` are used directly, so the package
declares no venue dependency at all.

### 3. The venue edge does its job

Every ADR-001 §8 / ADR-002 §7 obligation is discharged in the adapter, not
pushed at the domain boundary:

- `""`, `null`, and an absent key collapse to **absent**; an absent best bid is
  never turned into `"0"`.
- Venue decimal spellings are canonicalized through `@polymarket-bot/decimal` —
  the same implementation the domain schemas validate against. The wire is
  demonstrably non-canonical (`"last_trade_price": "0.090"` in the venue's own
  example).
- Every epoch-like form the SDK accepts is accepted, including the date-like
  string.
- An unrecognized free-string value is first-class **UNKNOWN**, reported with
  the raw frame attached.
- A 31-byte hex condition id is accepted, and so is every other length **up to
  the frozen domain identifier bound of 200 characters**; the fixture
  catalogue's 31/32-byte narrowing is not inherited. *Corrected in remediation
  round 1 (finding M2): this bullet previously read "or any other length", which
  overstated it. Past 200 characters the id is rejected as an observable
  `INVALID_CONDITION_ID` problem, and the §9 row is therefore discharged in
  substance but not literally — see
  [remediation round 1](#remediation-round-1-2026-08-27), M2.*

Every payload is then parsed by its own domain contract before it is emitted; a
failure becomes a `PAYLOAD_CONTRACT_VIOLATION` problem rather than a malformed
document downstream.

### 4. Nothing is dropped, and no sequence number is invented

Every fact an inbound frame asserts becomes **exactly one** normalized event or
**exactly one** `PublicMarketProblem` carrying the raw value (§8.3), and the
contract suite asserts that accounting on a mixed frame. The unit is the
venue's: an element asserting one fact yields one outcome, and a `price_change`
batching N entries yields N, each with the element's `observedIndex` and its own
`entryIndex`. *Corrected in remediation round 1 (finding L1): this paragraph
previously said "every element … becomes exactly one", which the batched case
never satisfied.* Normalized events carry no sequence field: ordering is
`(gatewayEpoch, ingestSeq)`, which the gateway assigns (§9.4, ADR-002 §2.3).

### 5. Tick-size changes are emitted exactly

One `TradingParametersChanged` per `tick_size_change`, `changedParameters`
exactly `["tick_size"]`, `tickSize` the canonicalized `new_tick_size` and
nothing else — and the `tick_size` field that rides on a `book` snapshot never
produces one, because a snapshot restates a parameter rather than announcing a
change.

### 6. Feed health is data

`FeedConnected`, `FeedDisconnected`, `FeedStale`, `FeedGapDetected`, and
`FeedResynchronized` are emitted on the same stream as the market data. A
reconnection or a subscription **addition** opens a gap with
`requiresAuthoritativeSnapshot: true`; `FeedResynchronized` is **caller-driven
only**, because reopening a socket is not a recovery and this adapter cannot
observe that a snapshot was applied. *Amended in remediation round 1 (finding
H2): "a subscription change" is now precisely an addition — a removal advances
nothing and opens nothing — and the caller-driven acknowledgement must name the
open gap's exact generation.*

### 7. Three deliberate silences, each with its evidence

- `price_change.hash` is not emitted as `BookLevelChanged.venueBookHash`: the
  venue documents it as the "Hash of the order that caused this change", while
  `book.hash` is the "Hash of the orderbook content".
- `last_trade_price.transaction_hash` is not emitted as
  `PublicTradeObserved.venueTradeId`: one settlement transaction can carry
  several trades, so it would silently deduplicate distinct ones.
- `price_change.best_bid`/`best_ask` do not produce a second
  `BestBidAskChanged`: the venue has a dedicated top-of-book event, and a rival
  synthesized stream would leave two contradictory histories.

## assumptions

### 1. C-1 / U-1: CONFIRMED against current official sources (2026-08-27)

The workplan criterion, verbatim: "Book price-change semantics (C-1/U-1
absolute-size zero-removal) are confirmed against current official sources or
recorded observation; on confirmation the provisional rule is ratified,
otherwise the affected contracts are flagged for an ADR-governed revision. The
provisional behavior is never asserted as settled without this evidence."

**Outcome: confirmed by documentation, not by observation.** No live connection
was made and no observational claim is made anywhere.

**What changed since 2026-08-24.** The URL the frozen report cites,
`https://docs.polymarket.com/market-data/websocket/market-channel`, now redirects
(HTTP 200 after redirect) to
`https://docs.polymarket.com/market-data/realtime-data#market-stream`. That page
still does not state the semantics. A **new** page not in the frozen report's
source index does:
`https://docs.polymarket.com/api-reference/wss/market` ("Market Channel — Public
WebSocket for real-time orderbook, price, and market lifecycle updates"),
published as an AsyncAPI document and also served as
`.../api-reference/wss/market.md`. All quotes below are from that page,
retrieved read-only and unauthenticated on **2026-08-27**.

Verbatim, from the `price_change` message definition:

> `size` — `New aggregate size (0 means level removed)`

> `price` — `Price level affected`

> `hash` — `Hash of the order that caused this change`

> `timestamp` — `Unix timestamp in milliseconds`

Verbatim, the operation and payload descriptions:

> `Delta update to orderbook price levels when an order is placed or cancelled`

> `Orderbook price level delta update`

Verbatim, from the `book` message definition, corroborating the aggregate
reading:

> `Full orderbook snapshot sent on subscribe or after a trade`

> `bids` — `Aggregated buy orders by price level`; `size` — `Total size at this price level`

> `hash` — `Hash of the orderbook content`

**Reading.** The *message* is a delta — it reports only the levels that changed —
while the `size` it carries is the new **aggregate** size at that level, and `0`
removes the level. That is exactly the handoff §23 assumption `WP-000` retained
provisionally. `BookLevelChanged.size` therefore carries the venue value through
unchanged, `"0"` included, and no delta arithmetic exists anywhere in this
package.

Two corroborating quotes retrieved the same day:

- `https://docs.polymarket.com/market-data/prices-order-books`: "Bids are ordered
  by ascending price and asks by descending price, so the best bid and ask are
  the last entries in their respective arrays. Each response also includes a
  `hash` for the order-book state. Compare it with the previous response's hash
  to determine whether the book changed between reads."
- `https://docs.polymarket.com/market-data/realtime-data`: the market WebSocket
  address, the `assets_ids`/`type: "market"` subscribe frame, the
  `custom_feature_enabled` flag, the dynamic subscribe/unsubscribe frames, and
  "Send the text frame `PING` every 10 seconds; the server replies with `PONG`".

**What this package did NOT do.** It did not edit
`packages/domain/src/events/book.ts` (protected), did not edit
`docs/contracts/protected-contracts.md` §8 (protected), did not edit ADR-002 §8
(protected), and did not rename the `WP-000` fixture example
`level-removed-absolute-zero-UNVERIFIED` (`test/fixtures/venue/**` is not in this
packet's allowed paths, and a frozen fixture catalogue is not an implementer's to
relabel). The confirmation is therefore **flagged for orchestrator/ADR
ratification** — [`follow_up`](#follow_up) item 1 — and until that lands the
repository still says "provisional" in those four places. Nothing in this package
asserts the semantics are settled on its own authority; every statement of them
carries the source, the quote, and the retrieval date.

### 2. R-2 anchoring: how it works

Register item R-2 (`docs/contracts/protected-contracts.md` §8.1) is assigned to
this packet "for the venue-adjacent schemas it owns". The concern is that a hand
transcription of an SDK schema is a silent verification error when nobody checks
it.

**The mechanism is `test/contract/polymarket-public/sdk-anchor/`.** The anchor
table records, for every field of every venue schema this package owns, the
modifier the official SDK declares for it (`required`, `literal`, `.nullish()`,
`z.array(...).nullish()`, or `OptionalDecimalStringSchema`), together with a
commit permalink into the pinned reference commit. `anchor.test.ts` then makes
each row executable, in five ways:

1. **Field-set equality, both directions.** Every key of the package's zod schema
   must appear in the table, and every table row must appear in the schema. The
   schema's key list is read at runtime from `schema.shape`, so it cannot drift
   from a copy.
2. **Field count against the SDK.** Each anchor carries `sdkFieldCount`, the
   number counted in the SDK source at the pinned commit on 2026-08-27. Adding a
   field to both the schema and the table without re-reading the SDK changes the
   count and fails, which forces the re-read to be recorded rather than assumed.
3. **Accept/reject vectors per modifier, through the real entry point.** A
   `required` field must make the event fail when omitted and pass when present;
   a `.nullish()` field must accept `null` **and** absence; an
   `OptionalDecimalStringSchema` field must additionally accept the wire empty
   string; a `literal` must reject a foreign value. A modifier transcribed
   wrongly changes observable behaviour and fails. Nested schemas are driven
   through their parent event, so the test exercises the same code path
   production does.
4. **Citation hygiene.** Every anchor and every field citation must embed the
   pinned commit; a mutable `blob/main` link is rejected, so a later SDK change
   cannot silently invalidate a citation.
5. **Recorded divergences.** Where this package is deliberately looser than the
   SDK, the row must carry a written `sdkDivergence` reason. A divergence with no
   reason is indistinguishable from a transcription mistake, which is exactly
   what R-2 is about.

116 assertions run from that table. Five recorded divergences, all on the REST
book schema and all in the "accept more" direction: the SDK's 40-hex `hash`
(the venue's own API example prints 64), its 31/32-byte `market` bound (ADR-002
§7 forbids inheriting it), its `tick_size` conversion to a float literal
(ADR-001 forbids a float for an economic value), and `min_order_size`/`neg_risk`
which the SDK's REST schema requires while the SDK's own WebSocket book event
marks them optional.

**This does not close R-2 for the repository** — `WP-000`'s `checks.ts` is a
different package's transcription and is untouched here. It closes it for the
schemas this packet owns, which is what the register assigns.

### 3. Venue-fact assumptions (all cited, none invented)

- The market channel may deliver a **single event object or a JSON array of
  them** in one text frame. Basis: the official SDK's own market socket branches
  on `Array.isArray(message)` before dispatching
  (`packages/client/src/websockets/clob/market.ts` at the pinned commit). A
  client assuming one event per frame would lose every event after the first.
- `last_trade_price.side` is the **taker's** side. Basis: the API reference types
  it `BUY | SELL` and describes it "From taker's perspective". That is what
  licenses mapping it onto `PublicTradeObserved.takerSide`; `BUY → BID`,
  `SELL → ASK`.
- The `level` subscription field (`1 | 2 | 3`, default `2`) exists, and the
  reference documents no meaning for the three values. This package therefore
  **never sends it** and lets the server default apply.
- **U-2 remains unknown.** No server-side timeout or close code for a missed
  `PING` is published. The client measures only its own side; the 30 s default is
  the SDK's `CLOB_HEARTBEAT_STALE_MS`, evidence of what the SDK treats as dead,
  not of a server rule.
- **U-3 remains unknown.** No maximum `assets_ids` per subscription is published.
  No cap is imposed by default, and that is explicitly not a claim that none
  exists; `maximumAssetsPerSubscriptionFrame` exists so an operator can apply the
  real bound when it is known.

### 4. Architectural assumptions

- **The gateway envelopes; the adapter normalizes.** Normalized events carry
  `(eventType, schemaVersion, payload)` plus venue-supplied provenance and
  nothing else. `observedIndex` orders events *within one frame* only and is
  never a persisted ordinal.
- **Identity and versioning belong to the catalogue.** `InternalMarketId`, the
  YES/NO token assignment, `metadataVersion`, `parametersVersion` and
  `parameterVersionRef` all arrive through the `PublicMarketDirectory` port. A
  declined answer becomes a reported problem. In particular the adapter does
  **not** pair `assets_ids` with `outcomes` by index: the venue publishes two
  parallel arrays and documents no pairing rule.
- **`MarketResolved` is decided by the winning token**, compared against the
  catalogue's two outcome tokens, not by the free-text `winning_outcome` label.
  A resolution naming no winner is reported (`MISSING_WINNING_TOKEN`), never
  guessed at as a 50/50 — U-6 is still open.

## deviations

1. **A `README.md` was added to the package.** The packet asked for the C-1/U-1
   evidence to be recorded "in your package contract documentation"; the package
   had none, and `docs/contracts/**` is protected. `packages/polymarket-public/README.md`
   is inside the allowed paths and is that documentation.
2. **A REST book fixture is owned by this suite, not by `test/fixtures/venue/`.**
   `WP-000` froze no order-book REST examples and `test/fixtures/venue/**` is
   outside this packet's allowed paths, so
   `test/contract/polymarket-public/fixtures/clob-book-rest.json` carries the
   same provenance envelope (source URL, retrieval date, sanitized flag,
   provenance note) and is explicitly marked as not part of the frozen `WP-000`
   catalogue.
3. **The REST wire schema is deliberately looser than the SDK's in five places**,
   all recorded with reasons in the anchor table and in
   `src/venue/order-book.ts`. Two are ADR-mandated (the condition-id bound, the
   float tick size), one is forced by the venue's own contradictory published
   hash lengths, and two align the REST book with the WebSocket book event.
4. **`price_change.best_bid`/`best_ask` produce no `BestBidAskChanged`**, and
   `last_trade_price.transaction_hash` is not carried as `venueTradeId`. Both are
   deliberate non-emissions with recorded reasons (see [`summary`](#summary) §7);
   both drop a venue field from the normalized stream, and the raw frame is
   preserved by the recorder. Recorded here because a reviewer should challenge

## known_risks

1. **The C-1/U-1 confirmation is documentary, not observational.** The venue's
   own API reference now states the rule, which is the strongest available
   evidence short of a live capture, but no frame was ever observed. If the
   implementation and the documentation ever disagree, this package follows the
   documentation. Severity: low, but it is the reason the ratification in
   `follow_up` 1 should record "confirmed by documentation on 2026-08-27" rather
   than "verified".
2. **The frozen venue report is drifting.** The URL it cites for the market
   channel now redirects, and the page it redirects to publishes a *normalized*
   SDK event shape (`topic`/`type`/`payload`, `tokenId`, ISO timestamps)
   alongside the raw wire shape in its API tab. The raw shape still matches the
   frozen fixtures exactly. A future phase gate should re-issue the report with
   the new URL; nothing in this package depends on the old one.
3. **The venue's published `hash` length for a REST book is self-contradictory**
   (40 characters in the TypeScript tab, 64 in the API tab, for the same field).
   This package pins neither and compares the value only for equality, which is
   what the page says it is for. A consumer that assumed SHA-1 would be wrong
   half the time.
4. **Gap detection is connection-level, not message-level.** With no venue
   sequence number, a *silently missed message on a healthy connection* is
   undetectable by any client, and this package invents nothing to paper over it.
   What it detects — reconnects, subscription replacement, heartbeat staleness —
   is what §7.1 actually turns on. `WP-150` should not read the absence of
   `FeedGapDetected` as proof that no message was missed.
5. **`observedIndex` is easy to misread.** It orders events within one frame and
   nothing more. A consumer that persisted it as an ordinal, or compared it
   across frames, would have invented the sequence number §9.4 forbids. It is
   documented as such in three places, but it is a foot-gun.
6. **`PublicMarketDirectory` is unimplemented.** Until `WP-110` provides a real
   catalogue, every market event normalizes to an `UNRESOLVED_MARKET` problem.
   That is the honest behaviour, but it means an integration built on this
   package before `WP-110` will see problems, not events.
7. **Batch snapshot fetches are sequential.** The venue publishes per-endpoint
   rate limits as a volatile configuration snapshot this package does not model,
   so a recovery over many markets is slower than a fan-out would be. The
   alternative — an unbounded parallel burst on the recovery path — is how a gap
   becomes a throttled gap. Rate-limit-aware scheduling is `WP-310`'s.
8. **The staleness default is borrowed.** 30 s comes from the SDK's own
   client-side constant, not from any published server behaviour (U-2). A feed
   whose real server timeout is shorter would be closed by the server before this
   client notices; the reconnect path handles that, but the `FeedStale` event
   would not precede it.
9. **`markResynchronized()` is an assertion the caller makes.** The adapter
   cannot verify that a snapshot was applied. A caller that called it without
   applying one would publish a `FeedResynchronized` claiming a recovery that did
   not happen — the one hole the contract's pinned literal cannot close, because
   it is a caller-side lie rather than a representable document.
10. **`test/contract/polymarket-public/**` is not wired into any root script.**
    It runs from the package's `test:contract` script only. Root wiring is
    orchestrator-owned at merge (`follow_up` 3).

#### H1 — stale socket callbacks crossed the generation boundary

**Probe reproduction (unmodified candidate).** A temporary probe drove the
callbacks of a socket the feed had already replaced:

```
H1a events from the stale socket:
  [{"type":"BookSnapshot","provenance":{...,"connectionId":"conn-2","subscriptionGeneration":3,"observedIndex":0}}]
H1a problems: []
H1a raw frames: [{"connectionId":"conn-2","generation":3}]
```

Confirmed exactly as reported: a frame injected through the closed first socket
became a `BookSnapshot` attributed to `conn-2`/generation 3 with zero problems;
a stale `onOpen` advanced the generation and published a second `FeedConnected`
plus a gap; a stale `onError` relabelled the LIVE connection's next disconnect.

**Fix** (`src/feed/connection.ts`). `#connect()` now builds an immutable
`FeedSocketSession` *before* calling the socket factory — `{ connectionId,
socket, generation, retired }` — and all four closures capture it. `#isLive()`
gates every callback on `session === this.#session && !session.retired &&
status !== "stopped"`, and the session's `generation` is updated only while it
is live, so it freezes at the value it was serving. Per callback:

| Callback | Stale behaviour |
| --- | --- |
| `onMessage` | the raw frame is still handed to the recorder, stamped with the **stale** session's `connectionId`/generation, then reported as a new `STALE_CONNECTION_FRAME` problem carrying the frame. Never published as current data; never dropped (§8.3) |
| `onOpen` | the abandoned socket is closed; no event, no generation change, no timers |
| `onError` | ignored |
| `onClose` | ignored (its disconnect was published when the session was retired) |

The live paths were corrected to read the session rather than the mutable field:
the normalization context, the raw-frame stamp, `FeedConnected`,
`FeedDisconnected`, `FeedStale` and `#sendFrames` all use `session`.
`#socket`/`#connectionId` are gone; a `connectionId` getter replaces the latter.

**Tests** (`src/feed/connection.test.ts`, describe `stale socket callbacks

#### H2 — gap closure and generation transitions were not authoritative

**Probe reproduction.**

```
H2a generation 2 → 3 { emittedGap: false, awaitingSnapshot: false }
H2b FeedResynchronized count with NO open gap: 2
H2c gap gen 3, newer gen 4 → awaitingSnapshot: false,
    published FeedResynchronized { subscriptionGeneration: 4 }
```

All three reproduced: an unsubscribe moved the generation with no gap; two
acknowledgements with no gap open published two recoveries; an acknowledgement
intended for generation 3 closed the newer generation-4 gap and published a
recovery naming a generation nobody had recovered.

**Fix.** Two halves, and they are one rule.

1. `MarketSubscriptionManager.remove()` **retains** the generation
   (`src/feed/subscriptions.ts`). The venue's dynamic `unsubscribe` frame drops
   only the named assets, so nothing still subscribed missed anything; the frame
   is still sent. Of the two options the review offered, this is the one that
   does not demand an authoritative snapshot for markets whose stream never
   broke. The resulting invariant — **on a live connection the generation
   advances exactly when a gap is opened for it** — is now a test.
2. The open gap is state, not a boolean: `#gap: OpenFeedGap | undefined`
   (`reasonCode`, `subscriptionGeneration`, `connectionId`, `detectedAt`),
   exposed read-only as `feed.openGap` so a caller can name what it owes.
   `markResynchronized(acknowledgement)` now takes
   `{ subscriptionGeneration }` and returns a typed
   `FeedResynchronizationOutcome`: `NO_OPEN_GAP` when nothing is owed (which is
   also what refuses a duplicate), `GENERATION_MISMATCH` when the
   acknowledgement is not the open gap's, and only otherwise does it close the
   gap and publish `FeedResynchronized` for **the gap's** generation. A newer
   gap supersedes an older one and says so in its `detail`. A rejection is
   returned rather than thrown, because a late snapshot is a race, not a defect.

   The acknowledgement deliberately carries no snapshot identifier:
   `FeedResynchronized` has no field to publish one in, and accepting evidence
   the adapter would then discard would be theatre. The generation is the
   identity that matters, because every gap this feed opens is opened by a
   transition that also advanced it.

**Tests.** `src/feed/connection.test.ts`: `markResynchronized` (accepted;
`NO_OPEN_GAP`; duplicate; `GENERATION_MISMATCH`; `openGap` names the gap) and
`subscription changes and the generation (H2)` (addition opens a gap under the
new generation; removal changes nothing; the "advances exactly when a gap opens"
invariant swept over add/remove/no-op/reconnect; supersession).
`src/feed/subscriptions.test.ts` pins the removal rule at the manager level.
`test/contract/polymarket-public/feed-lifecycle.test.ts` runs the whole
fetch-then-acknowledge cycle and the stale-acknowledgement race end to end.

**Mutation check.**

```
H2-gap-required      : failed (good) | refuses an acknowledgement when no gap is open, and publishes nothing
                                      | refuses a DUPLICATE acknowledgement of the same gap
H2-generation-match  : failed (good) | refuses a snapshot taken for an older generation than the open gap's
                                      | a newer gap supersedes an older one, and only the newer can be closed
H2-removal-generation: failed (good) | a REMOVAL neither advances the generation nor opens a gap
                                      | on a live connection the generation changes exactly when a gap opens
                                      | (manager) does NOT advance on a removal
```

**Caller-visible change.** `markResynchronized()` is now

### Assumptions added this round

1. **`timestamp` and `last_trade_price` may be absent on the REST book.** The
   official OpenAPI lists both under `required`; the SDK's own client for the
   same endpoint declares both `.nullish()`. This package follows the SDK for
   these two only, on the reasoning that a market that never traded has no last
   trade price and that rejecting a whole book on a recovery path is the worse
   failure. Both are recorded as `presence` divergences with that evidence, and
   absence maps to ABSENT, never to `"0"`. **A reviewer should challenge this
   rather than discover it.**
2. **A removal does not invalidate the remaining assets.** The venue documents
   `{"operation":"unsubscribe","assets_ids":[…]}` as removing the named assets;
   nothing published says it disturbs the rest of the subscription. The rule
   chosen (retain the generation) follows from that. If the venue in fact
   re-establishes the whole subscription on an unsubscribe, the correct choice
   would be the review's other option — open a gap — and the invariant test
   would be the place to flip it.
3. **The empty string stays acceptable for a required REST decimal.**
   `min_order_size: ""` and `tick_size: ""` still parse, because the SDK's
   `DecimalStringSchema` is `z.string()` and ADR-002 §7 forbids being stricter
   than the SDK at the wire layer. The empty string collapses to ABSENT and
   neither field reaches a domain payload from this package. `hash: ""` IS
   rejected, because the hash's value-form relaxation is about length.

### Known risks added this round

1. **`markResynchronized` changed shape.** It now requires the acknowledged
   generation and returns an outcome a caller can ignore. `WP-120` must handle
   the rejection branch; ignoring it would leave a gap open and no recovery
   published — visible in `feed.openGap`, but silent otherwise.
2. **A stale frame is reported, not normalized.** The data in it is real, and
   this package deliberately does not publish it: it belongs to a subscription
   generation the feed no longer holds, and §7.1 requires an authoritative
   snapshot for that boundary anyway. The raw frame is preserved and the problem
   carries it, so nothing is lost — but a consumer that wanted late data would
   have to take it from the problem stream.
3. **The REST book is now strict about eight fields.** If the venue ever omits
   one of them, this adapter refuses the whole snapshot rather than emitting a
   partial one. That is the intended failure mode for an authority a gap
   recovery rebuilds from, and both first-party sources agree the fields are
   required — but it is a stricter posture than the reviewed commit had.
4. **`entryIndex` is a second foot-gun of the same family as `observedIndex`.**
   It orders outcomes inside one frame element and nothing else. A consumer that
   persisted `(observedIndex, entryIndex)` as an ordinal would have invented the
   sequence number §9.4 forbids.

#### R2-H1 — a synchronous `onOpen` published `FeedConnected` having sent nothing

**Probe reproduction (unmodified `d71eb85`).** A factory whose transport is
already connected — it calls `handlers.onOpen()` before returning the handle:

```
SYNC_OPEN {"sent":[],"eventTypes":["FeedConnected"],"generation":2,"connectionId":"conn-1"}
```

Byte-for-byte the reviewer's output. `#connect()` assigned `session.socket`
*after* the factory call, so `#onOpen` → `#sendFrames()` found no socket and
returned; the generation still advanced to 2 and `FeedConnected` was published.
The feed then believed it was subscribed to a socket it had sent nothing on, and
nothing anywhere would have said otherwise.

**Fix** (`src/feed/connection.ts`). A per-attempt deferred-action queue, in the
shape WP-090 proved:

- `FeedSocketSession` gains `deferred: SocketAction[]`.
- `#withSocket(session, action)` runs the action if the handle exists and queues
  it otherwise. **Every** socket-dependent thing the feed does goes through it:
  the subscription send, the heartbeat `PING`, the staleness close, `stop()`'s
  close, and the abandoned-socket close.
- `#connect()` assigns the handle and then drains the queue in request order.
  Work queued for a session that has since been retired still runs — that is how
  an overtaken attempt's socket gets closed instead of leaked.
- `#onOpen` defers its **whole** body (`#handleOpen`) rather than only the send,
  so the published order is the documented one in both the synchronous and the
  asynchronous case: plan → write the subscription → publish `FeedConnected`. A
  consumer never sees "connected" for a socket the subscription has not reached.
  `#handleOpen` re-checks liveness *after* the deferral, because the attempt can
  be overtaken or stopped between the callback and the handle.

`#sendFrames` also now takes the session explicitly instead of reading
`this.#session`, for the same reason every callback carries one.

**Tests.** `src/feed/connection.test.ts`, describe *"a transport that is already
connected when the factory returns (round-2 H1)"*, four cases:

| Case | What it pins |
| --- | --- |
| sends the subscription, and only then publishes `FeedConnected` | the frame is on the socket **and** `sent.length === 1` at the instant the event reaches the caller — order, not just presence |
| resubscribes when the RECONNECT's transport is already connected | the reconnect path, not only the start path |
| closes the socket when `stop()` runs inside a synchronous callback | `stop()` with no handle yet still closes when the handle arrives |
| neither sends on nor leaks an attempt overtaken before its handle arrived | an open+close inside one factory call: nothing sent, socket closed, no `FeedConnected`, no gap |

Plus one end-to-end case in `test/contract/polymarket-public/feed-lifecycle.test.ts`
(*"subscribes a transport that was already connected when the factory
returned"*), which drives start, a fixture frame, and the reconnect through the
same pre-opened transport. The transport itself is a new
`fakeWebSocketFactory({ onCreate })` hook in `src/testing/index.ts`: the double
could not previously emit anything during the factory call, which is precisely
why the original suite could not express this.

**Mutation check.**

```
A  remove the #onOpen deferral            : failed (good) | sends the subscription, and only then publishes FeedConnected
                                                          | neither sends on nor leaks an attempt overtaken before its handle arrived
B  revert stop() to a direct socket close : failed (good) | closes the socket when stop() runs inside a synchronous callback
C  make #sendFrames drop with no handle   : 39 passed — NOT killed on its own (see below)
A+C combined                              : failed (good) | sends the subscription, and only then publishes FeedConnected
                                                          | resubscribes when the RECONNECT's transport is already connected
                                                          | neither sends on nor leaks an attempt overtaken before its handle arrived
```

Disclosed honestly: mutation C alone is not killed, because with the whole open
deferred `#sendFrames` is never reached without a handle. Its queueing is
defence in depth, and A+C shows the pair is jointly load-bearing — with the open
deferral gone, `#sendFrames`'s own queue is what still delivers the frame.

#### R2-H2 — an empty reconnect opened a gap an OLD acknowledgement could close

**Probe reproduction (unmodified `d71eb85`).** Connect with one asset at
generation 2, remove the last asset, disconnect, reconnect, acknowledge
generation 2:

```
EMPTY_RECONNECT {"oldGen":2,"currentGen":2,
  "gap":{"reasonCode":"FEED_RECONNECTED","subscriptionGeneration":2,"connectionId":"conn-2",
         "detectedAt":"2026-08-27T12:01:00.000Z"},
  "ack":{"status":"accepted","subscriptionGeneration":2},"awaiting":false,"sent":[]}
```

Exactly as reported. `planFullSubscription()` of an empty set resubscribes
nothing and (correctly) does not advance the generation, while `#onOpen` opened
the reconnect gap unconditionally — so the new gap carried the generation the
previous one had already used, and an acknowledgement written for that older gap
closed it. The stated invariant ("every opened gap is paired with a generation
advance") was therefore false, and the round-1 sweep missed it because every
reconnect it swept still had an asset subscribed.

**Fix.** Of the reviewer's two options, the one that is also semantically right:
**do not open a reconnect gap when there is nothing to recover.** `#handleOpen`
opens the `FEED_RECONNECTED` gap only when `subscription.assets.length > 0`.
With no asset subscribed there is no affected market, nothing was missed, and
demanding an authoritative snapshot for an empty subscription would be the
round-1 H2 mistake in another costume. Gap identity needed no new field: with
this change every gap-opening transition advances the generation in the same
step, so gap generations are unique and strictly increasing and the generation
alone is an unambiguous acknowledgement id.

**The invariant, restated accurately** (now written in `connection.ts` invariant
4, `OpenFeedGap.subscriptionGeneration`, `subscriptions.ts`, and README §6):

> Every gap this feed opens is opened by a transition that advances the
> subscription generation **in the same step** — an addition pushed to a live
> connection, or a full (re)subscription of a **non-empty** set. Gap generations
> are therefore unique and strictly increasing.
> **The converse is not claimed:** the generation also advances where nothing was
> missed and no gap is owed — the first connection, and any change made while
> disconnected.

The round-1 wording ("on a live connection the generation advances exactly when
a gap is opened for it") is kept only where it is true — as the *live-connection*
equality, which the sweep still asserts step by step — and is no longer offered
as the whole rule.

**Tests.** `src/feed/connection.test.ts`:

- describe *"a reconnect with nothing subscribed (round-2 H2)"* — four cases:
  the probe itself (no gap, no frame, `FeedConnected` only); the acknowledgement
  that used to close the phantom gap is refused `NO_OPEN_GAP`; a spent
  acknowledgement replayed after an empty reconnect publishes nothing (exactly
  one `FeedResynchronized` in the whole lifetime); and a gap opens again as soon
  as there is something to recover.
- the sweep is rewritten as *"every gap opens under a generation no gap has
  used, swept over every transition"*: nine scripted steps — add, remove, no-op
  add, reconnect with assets, remove the LAST token, **reconnect empty**,
  reconnect empty again, subscribe on the live connection, reconnect with assets
  — asserting per step that (a) a gap never opens without the generation moving
  with it, (b) a gap never reuses a generation an earlier gap claimed, and (c)
  the live-connection equality still holds; then that gap generations are
  strictly increasing and that every spent generation is refused.
- `test/contract/polymarket-public/feed-lifecycle.test.ts` — *"owes no snapshot
  for a reconnect with nothing subscribed"* runs the whole cycle end to end:
  a real gap acknowledged, then unsubscribe-all, drop, reconnect empty, and the
  replayed acknowledgement refused.

**Mutation check** (restore the unconditional gap):

1. **A reconnect with nothing subscribed owes nothing.** Round-2 H2 offered two
   remedies; this one rests on the reading that a `subscriptionGeneration`
   boundary exists to say "the server-side subscription was replaced, expect a
   snapshot for the affected markets", and that with no asset subscribed there
   is no affected market. If a future consumer needs "the socket was replaced"
   as a signal independent of subscription state, the honest way to give it is a
   distinct event — not a gap whose identity would then collide.
2. **A queued action outlives its session on purpose.** Work queued before the
   handle arrived runs even if the session was retired in the meantime, because
   the alternative is an abandoned socket nobody closes. Only the open re-checks
   liveness; the other queued actions are closes, which are correct either way.
3. **`_def` is a stable-enough zod internal for a test-only guard.** The L1
   traversal reads zod 4's internal descriptor. That is a deliberate test-side
   coupling, bounded by the canary direction: if the internals move, the guard
   fails loudly rather than silently covering nothing.

### Known risks added this round

1. **A frame delivered synchronously by the factory, before the open is
   processed, is stamped with the pre-subscription generation.** With `#onOpen`
   deferred as a unit, a transport that calls `onMessage` inside the factory call
   (after `onOpen`, before returning) has its frame handled while the feed is
   still `connecting`. The frame is recorded, normalized and stamped with the
   session's generation at that instant — which is the generation it genuinely
   arrived under, since the subscription had not been written yet. No real
   transport does this, and no fixture exercises it; it is disclosed because the
   deferral is what creates the ordering.
2. **`FeedGapDetected` is now conditional on the desired set.** A consumer that
   counted "one gap per reconnect" will see none for a reconnect with nothing
   subscribed. That is the point of the fix, but it is an observable change from
   the reviewed commit.
3. **The L1 guard is total over what it can reach, not over what could exist.**
   A module-private object schema used only inside a function body would still be
   invisible. None exists; the boundary is written into the test.

### Follow-up added this round

1. **`WP-120` should treat `openGap === undefined` after a reconnect as normal.**
   With an empty subscription there is no gap and nothing to fetch. The gateway's
   recovery policy should key off `feed.openGap`, never off "a reconnect
   happened".
2. Round-1 follow-ups 1–3 (contract-owner item 3 on the 200-character cap, the
   cross-adapter meaning of `takerSide`, and re-issuing the venue report with the
   `GET /book` OpenAPI) are unchanged and still open.
