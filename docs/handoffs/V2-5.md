## summary
1. **The pin** (the §W.1 five-step check, 2026-10-06).
   - npm `latest` is 0.12.0, and the integrities equal `verified-2026-10-05.md` §S.1. Both attestations name provenance commit `71f9723f70f065af79670ac6269ab51729fcfb5e`.
   - The changelog has no "breaking" or "removed".
   - It is recorded in `docs/runbooks/signer.md` §7.1.
   - The lockfile diff touches only the two packages, `zod` stays 4.4.3, and the audit is clean.
2. **A security fix found by the upgrade.** 0.12.0's `ServiceClient` takes a snake_case `error` text as the `code` for any status but 400. So a 503 `{"error":"post_only_mode"}` would have become the documented POST_ONLY refusal: NOT_APPLIED, with cancels allowed. That is exactly what the 2026-09-30 report §2.4 forbids.
   - `error-mapping.ts`'s rule 4c trusts a documented code only when the SDK's own message does not show it was inferred.
   - Such a body is TRADING_UNAVAILABLE / UNKNOWN again, as under 0.11.0, fail-closed.
3. **The V2 behaviour,** pinned through the real SDK:
   - V2 ids sign against ExchangeV3 with domain "3", and V1 ids against the CTF Exchange or Neg Risk with "2" (F-47);
   - a V2 SELL's balance read carries `asset_type=CONDITIONAL-V2` (F-53).
4. **Hidden behaviours,** pinned:
   - DELETE and GET make 3 attempts on a network error, and POST makes exactly 1;
   - each attempt times out at 10,000 ms, and a timeout is never retried;
   - market metadata is cached for 10 minutes.
5. **The port.** The ten-member port is unchanged, and a type-level pin forbids any `place*` member. The `ASSET_ID` hex branch is removed (C6).
6. **The bundle.** The ops-cli bundle builds with 0.12.0 inputs and loads.
7. **Rounding is unchanged:** shares round down to 2 decimals for every tick. `CO3-N1` still holds.
