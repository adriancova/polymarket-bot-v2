## summary

1. **Local token budgets** (`RateLimitBudget`).
   - There is one budget per §9.13 dimension:
     - IP endpoint classes, as sliding windows, with burst and sustained limits where documented;
     - each signer's own order bucket and cancel bucket;
     - the relayer.
   - **Priority.** Requests are granted in the §9.13 priority order, first come first served within a class.
     - A waiting higher-priority request holds its cost on every budget it uses.
     - Each class leaves a configured share of every budget unused, so a lower class cannot drain what a safety class needs.
     - An operation can be filed only under classes its kind allows.
   - **Configuration.** Every limit, rate, burst, token cost and policy number comes from a validated configuration snapshot with a source and an effective time.
     - Snapshots take effect at exactly their effective time, and refill is computed piecewise across changes.
     - Before the first snapshot, every request is refused.
   - **Cancel-all.** It is charged one token when granted, then one per canceled order. Tiers that allow it may go into debt (D-21).
2. **Response-header feedback.**
   - Only the five documented headers are read:
     - Remaining only lowers the local estimate;
     - Reset imposes a wait only during a wait period;
     - Tier switches the signer's buckets;
     - Warning drops the estimate to zero.
   - A 429's Retry-After blocks exactly that long, on the bucket that was charged.
   - Any other header is flagged by name, and its value is never read.
3. **Venue modes** (`VenueModeDetector`).
   - Modes are keyed on HTTP status and the documented code, never on error text:
     - **425:** no placement until Retry-After, or a bounded backoff, then post-only for the configured two minutes, anchored on evidence (round 1);
     - **post-only 503:** post-only for its Retry-After, or the window if none is given;
     - **503 without a code:** placements pause for a configured time;
     - **cancels:** always allowed.
   - It feeds the OMS's existing venue-mode input through `venueModeSource` and `withModeDetection`.
   - The 425 resend still follows WP-270 decision 2.
   - Against the real `OrderManager`, a non-post-only order is shown never to be blindly retried, on five paths.
4. **Citations.** Every venue fact acted on is quoted, and tests check each quote verbatim against `docs/venue/` or the pinned SDK's type declarations.

## assumptions
- **The §9.13 "signer" dimension** means each signer's own order and cancel buckets. **The relayer** means the documented `/submit` IP limit.
- **IP classes:** a request is charged to every class its operation lists. Whether the classes nest is undocumented, so charging all of them is the conservative choice.
- **The meanings of Reset and Remaining** come from the pinned `@polymarket/client@0.11.0` type declarations, which handoff §1.1 allows, and are tested against them.

## deviations
- **The `test:contract` line is in `polymarket-secure`'s manifest.** The OMS manifest's scripts are pinned exactly by a test outside the paths.
- **Test snapshots live in `*.test-support.ts` files** inside `src/`. WP-260's source-hygiene scan still covers them.

## known_risks
- **CX310-R3-01 (LOW).** A 429 that completes one in-flight grant withdraws a pending wait that may belong to another concurrent response. Both verifiers reproduced it. It is LOW because the venue's answers do not say which request a header belongs to.
- **OP-R3-01 (LOW).** Three guards from the round-2 fix (`#holdBalance`, `#release`, `#holdWait`) are correct but unpinned.
- **The IP budgets are per process.** The data gateway and the ops CLI share the host's IP but not this budget.
- **Batch cancels above a bucket's burst are refused,** so callers must split them. Cancel debt after a large cancel-all is real (D-21): 4,775 ms after 500 canceled orders on Standard.
- **Cold start.** A signer seen for the first time starts with empty buckets.
- **Carried INFOs:**
  - OP-R1-08: cancel-all can be filed as a stale-quote cancel; only a downgrade is possible.
  - OP-R1-09: a cancel-all without a canceled count gets no debit; WP-330 should pass the count.
  - OP-R2-04: a request held back by an operation wait still reserves against lower classes.
  - OP-R2-05: liveness after a 425 needs a probe.
  - OP-R2-06: the engine-return evidence assumes validation never precedes the restart check.
