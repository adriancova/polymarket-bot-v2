## summary

1. **WP300-R10-01 is closed.**
   - **The defect.** While the executor call was pending and the operation was still PLANNED, a terminal answer could name a request never issued for the operation. It was kept like an observation, then applied after the executor's SUBMITTED. A value operation then released its reservation, or an approval became ready after a sync.
   - **The fix.** In `#answer`, the in-flight gate now also applies while PLANNED and submitting. Such an answer, from any source, is refused `WALLET_OP_EVIDENCE_SUPERSEDED` and never kept. It sends the operation to UNKNOWN through `#toUnknown`. That weighs every kept observation, and then the answer, before the reconciliation request goes out.
   - **Why route it rather than refuse it.** Refusing without keeping would discard evidence, which WP300-R7-X1 forbids. Routing reuses the reviewed in-flight path, and the outcome no longer depends on arrival order.
   - **Docs.** The module header, the `resolveByReconciliation` documentation and the comments now state the refusal code for each state.
2. **The tripwire.** `venue-citations.test.ts` now has the same `fetch` tripwire as `split-merge-redeem-fixtures.test.ts`, asserting 0 calls. It caught both planted fetches. This closes `CI-4`'s known risk.

## assumptions
- No reconciliation request is ever issued while an operation is PLANNED. So any `requestId` named while PLANNED is not one of the operation's own.
- An answer that names no request while PLANNED is current under the request contract. It is unchanged, and so is `observe()`.

## deviations
- Only the 6 defect cases of the 11 round-10 probe cases fail on base. The other 5 are controls whose behaviour this round keeps on purpose.

## known_risks
- **Predictable request ids (LOW; present before this round).** Suppose an answer names this operation's next request id before that request is issued, and is then delivered again after the id is issued. It then counts as current. This needs a reconciler that answers before it is asked, which the request contract forbids, or a replay.
- **WP300B-R1-01 (LOW).** Evidence `state` is read twice. A Proxy whose descriptor changes between the reads (MINED, then FAILED) can conclude the operation. Proxy inputs are a disclosed WP-300 limit.
- **WP300B-R1-02 (LOW; present before this round).** `ownData` treats a getter or inherited `requestId` as "names no request".
- **WP300B-R1-03 (LOW).** The documentation says `WALLET_OP_EVIDENCE_SUPERSEDED`. Terminal shapes the classifier reads as unrecognised get `WALLET_OP_ILLEGAL_TRANSITION` instead. The money behaviour is correct.
- **WP300B-R1-04 (LOW).** Both tripwires are installed in `beforeEach`, so they do not cover code evaluated at module load.
- **Unchanged since WP-300:** the in-flight trust boundary, the reconciler-dependent liveness, and the in-memory state (`WP300-PERSIST`).
