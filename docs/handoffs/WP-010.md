## summary

Created the reproducible pnpm/TypeScript monorepo baseline. Root workspace
pins Node `>=24` (engines) and `pnpm@11.17.0` (packageManager).
`tsconfig.base.json` enables `strict`, `noUncheckedIndexedAccess`,
`exactOptionalPropertyTypes`, and related strictness flags. All six handoff §5
apps and all 28 §5 packages (including `packages/strategies/static-bracket`;
`domain`/`decimal` are contract-free scaffolds reserved for WP-020) exist as
minimal compilable placeholders (package.json + tsconfig extending the base +
trivial `src/index.ts` exporting only a package-name constant — no invented
APIs). Quality gates: `pnpm typecheck` (recursive `tsc --noEmit` + test tree),
`pnpm lint` (ESLint 9 flat config with typescript-eslint), `pnpm test`
(Vitest, 2 real smoke tests), `pnpm test:integration` (documented exit-0 skip
notice until WP-040+; other §22 surface scripts fail loudly with
"NOT IMPLEMENTED until WP-xxx" and exit 1). `docker-compose.yml` pins
`postgres:16.6-alpine` / `redis:7.4.2-alpine`, binds `127.0.0.1` only, uses
obvious dev-only credentials. `python/` uv workspace with committed `uv.lock`
and passing pytest. CI at `.github/workflows/ci.yml` (Node 24 + pnpm gates,
uv sync --frozen + pytest; no secrets, `permissions: contents: read`).
No venue SDK, no credentials, no economic `number` fields anywhere.

## assumptions

- "Placeholder scripts fail gracefully" is satisfied by exit-1 with clear
  "NOT IMPLEMENTED until WP-xxx" messages for `test:replay`, `db:migrate`,
  `dev:*`, `ops:*`; `test:integration` uses the exit-0 skip-notice option,
  chosen and documented in the script text and vitest config comment.
- Node pin: `engines` field + `packageManager` in root `package.json` used as
  the "pinned in the repository" mechanism (a root `.nvmrc` was not in
  WP-010 `allowed_paths`); the smoke test asserts Node major ≥ 24 at runtime.
- Strategy scaffold package is named `@polymarket-bot/strategy-static-bracket`.
- pnpm 11 auto-inserted an `allowBuilds` entry into `pnpm-workspace.yaml`;
  `esbuild: true` was accepted (Vitest's bundler postinstall, dev-only).
- Dev-only compose credentials (`devlocal` / `devlocal-only-not-a-secret`)
  are acceptable because they are self-describing placeholders bound to
  loopback only.

## known_risks

- GitHub Actions has never executed: the repository has no remote. `ci.yml`
  is YAML-validated only; a real CI run remains pending external evidence.
- Compose validation on the development host requires
  `PMB_POSTGRES_PORT=15432` (native PostgreSQL occupies 5432 there);
  defaults are unchanged for other environments and CI.
- ESLint is currently non-type-aware (recommended presets); enable type-aware
  linting once packages contain real code.
- Resolved dependency versions drifted above spec floors (eslint 9.39.5,
  typescript 5.9.3, vitest 3.2.7, typescript-eslint 8.67.0) — pinned exactly
  via `pnpm-lock.yaml` / `uv.lock`.
- `pnpm test:integration` remains an exit-0 placeholder with zero coverage
  until WP-040+; compose infrastructure health is gated separately
  (`pnpm test:compose` and the CI `compose` job), so the placeholder is not
  the only infrastructure signal.
- Vulnerability scanning reflects advisory databases at run time; a pass is
  not a permanent guarantee.
