## Dates, method and rules

- **Date and file name.** Every fetch was performed on **2026-09-30 UTC**
  (documentation and SDK fetches 05:11:49–05:20:20Z, no-follow status probes
  05:14:56–05:22:45Z). The file is named by that date, the convention of every
  prior dated report. Each source row in §14 carries its own UTC timestamp.
- **Method.** Read-only, unauthenticated `curl -sS -L` GETs of (a) the
  official documentation at `docs.polymarket.com` in its served `.md` form,
  (b) the rendered URLs VENUE-2 probed, requested **without** following
  redirects, (c) the official SDK repository `Polymarket/ts-sdk` through
  `api.github.com` (commit, compare, tree, repo metadata) and
  `raw.githubusercontent.com` (file bodies at named commits), and (d) the npm
  registry's **package metadata** for `@polymarket/client` and its published
  provenance attestation (`registry.npmjs.org`, metadata only; no tarball was
  downloaded or installed). Byte counts are curl's `size_download`; digests are
  `sha256sum` over the saved bodies.
- **Baseline and how drift was computed.** VENUE-2's saved response bodies
  survive on this machine and their SHA-256 digests match
  `verified-2026-09-16.md` §14 row for row (checked this round). Every
  re-fetched page was therefore compared **byte for byte** with its VENUE-2
  body, and every changed page was also compared after a **format
  normalization** (runs of spaces and tabs collapsed, Markdown table-separator
  rows reduced to `|-|`, whitespace around `|` removed). The documentation site
  re-rendered every Markdown table between the two rounds (column padding
  removed, `| --- |` → `| - |`), so a raw diff alone overstates change. Result:
  8 pages byte-identical, 16 pages changed **only** in table formatting, 2
  pages changed only in `$` escaping, and the remaining changes are
  substantive and are each a drift row below (§14 records which is which).
- **Drift rule.** A difference from the VENUE-2 text (and through it the frozen
  2026-08-24 text) is a numbered `E-nn` row quoting the previous and current
  text, naming the source, the repository consequence (`file:line`) and the
  owning package. Additions that bear on this repository are drift; additions
  with no consequence are listed in-section without a row. Pages indexed for
  the first time this round cannot "drift"; where one contradicts another
  official page, the contradiction is a §11 conflict, and where it adds a fact
  a Wave 3 package needs, it is recorded in §W.
- **Precedence** (handoff §1.1): current official documentation and current
  official SDK behaviour control venue facts. Where they differ, both are
  quoted; nothing that only the SDK says is presented as documentation (§12).
- **This round records; it does not re-implement.** No `packages/**`,
  `apps/**`, fixture payload, ADR, spec or earlier dated report was edited.
- **Out of scope:** the Perps product surface (`/perps/**`, Perps API
  reference, Perps SDK code). Perps commits and files in the SDK diff are
  listed in §W.1 only so the diff is complete; nothing is asserted about Perps.

### 2.4 Error taxonomy — verdict **UNCHANGED on the guide page; evidence for U-4 widened**

The guide page still documents example causes only. The newly indexed CLOB
OpenAPI documents an `ErrorResponse` schema `{ error: string (required), code?:
"Machine-readable error code, when provided", retry_after_seconds?: integer }`
(S-D49 lines 287–301) and example bodies per status (S-D49 lines 119–202;
S-D50 lines 160–220; S-D51–S-D54):

- `400`: "Invalid order payload"; "the order owner has to be the owner of the
  API KEY"; "the order signer address has to be the address of the API KEY";
  "'0x1234...' address banned"; "'0x1234...' address in closed only mode";
  "order 0xabc... is invalid. Price (100) breaks minimum tick size rule: 0.1";
  batch "Too many orders in payload: 20, max allowed: 15"; cancel "Invalid
  orderID", "Too many orders in payload, max allowed: 1000".
- `401`: "Invalid API key". `500`: "could not insert order" / "Internal server
  error".
- `503`: "Trading is currently disabled. Check polymarket.com for updates";
  "Trading is currently cancel-only. New orders are not accepted, but cancels
  are allowed."; post-only `{error, code: "post_only_mode",
  retry_after_seconds: 79}` with a `Retry-After` header "Seconds to wait before
  retrying when provided by post-only mode" (S-D49 lines 170–202).

These are **examples, not an enumeration**; the only documented `code` value
is still `post_only_mode`. **U-4 stands** (register annotation added). SDK
note, not documentation: at the head commit (not in `0.11.0`) the SDK
**infers** `RequestRejectedError.code` from the `error` string when no `code`
is present, the status is not 400 and the string matches
`/^[a-z][a-z0-9]*(?:_[a-z0-9]+)*$/` (S-H-client_ServiceClient lines 309–318;
absent from S-R/S-A). None of the documented `error` strings above matches that
pattern, so the inference changes nothing documented today; `WP-260` must not
treat an inferred `code` as a venue-documented code.
